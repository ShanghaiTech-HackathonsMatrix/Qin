# 学业连接器与课表作业

沿用 Qin 的同步纯函数插件契约：`plan → 请求描述 → 宿主 IO → parsers → next`。插件不读 Cookie、密码、存储或系统时钟，也不执行网页脚本。连接器逐页累计保存 `academic_snapshot/current`；读取异常不会用空结果覆盖旧快照，可靠识别的本学期无课程则允许保存空结果。

## 本学期范围

- BB 只识别门户“未完成课程列表（Uncompleted Course List）”模块，忽略总课程与已完成课程。默认待完成作业扫描、手动目录扫描和旧作业轮转核对都限制在这个集合内。
- Gradescope 读取 Dashboard 的学期分组，在请求课程页前筛选当前学期。例如 2026 年 10 月只请求 Fall 2026，不请求 Spring 2026、Fall 2025 或未来学期。
- 当前春秋规则采用北京时间：2–7 月为 Spring 当年，8–12 月为 Fall 当年，1 月归 Fall 前一年。不以作业截止日期猜测课程学期；Summer/Winter 不混入春秋。
- `academic-term.ts` 为 App、有/无日期任务、学业投影、挂件和提醒提供同一筛选；旧缓存也过滤。个人改期不能将历史课程作业带回本期，撤销已排的历史学业提醒时保留自建提醒。教务课表及自建任务不受影响。
- 新 BB 快照的 `courseScope` 标记此次未完成分组对应的当前学期，跨学期后须重新同步；旧 BB 缓存仅从明确学期文字恢复。GS 学期分组未知、BB 模块未加载或结构未知时报告失败并保留缓存，不退回全量扫描。
- 日历边界不是学校实时校历；暂不支持暑冬学期或手动改学期，跨学期应及时联网同步。

## 分层

- `connectors.ts`：Gradescope、BB、教务的请求状态机。单次最多 600 页、选中课程最多 60 门，BB 最深 6 层。URL 规范化去重，过滤非目录工具入口；只有实际作业页生成 BB 作业。
- `html.ts` / `parsers.ts`：受限 HTML 与 EAMS `TaskActivity` 字面量解析。EAMS 从入口动态取学生及学期参数，再 POST 查询个人课表，不硬编码学生或学期。
- `model.ts` / `projection.ts`：源数据 + 用户设置 + 人工修正，生成课程与时间线事件。每轮最多 1900 条事件。
- 宿主 `AcademicService`：串行同步、配置与修正持久化、投影替换、提醒对账。源快照、人工修正、派生事件各自保存。
- 宿主请求适配器：GET/HEAD 遇本地限流时按 `retryAfterMs` 等待并继续同一页，等待受单请求超时及最多 8 次重试约束；配额不变，POST 不自动重发。
- Android `PlatformSessionProvider` / `PlatformLoginActivity`：独立进程与 WebView 数据目录。官方页面登录后由原生 HTTP 携带 Cookie 请求；精确限制平台 origin 和端口。登录 WebView 无 Capacitor 桥，不忽略 TLS 错误。

三个连接器仅是已内置第一方插件，并未实现动态插件市场。没有扩大通用 `auth.login`、`notify.local` RPC 的能力声明。

## 使用

1. Android 打开“课表作业 → 连接学习平台”。Gradescope 用邮箱密码；BB、教务用学校统一身份认证，学校认证 Cookie 由两个入口共享，无需另设教务凭证。
2. 在官方页面完成登录，点击“完成登录并同步”。应用根据实际课程/作业页判断结果，点击按钮本身不等于登录成功。
3. 教务同步后确认第 1 教学周的周一日期或当前周数。未确认时可看周课表，但不生成带日期的上课事件及提醒。
4. 设置课表名称、总周数、周末/非本周显示、上午下午晚上节数、课长和课间，并逐节修正作息。首次可采用教务识别作息，人工编辑后不再被自动覆盖。
5. 课程平台字段只读，详情可修改个人备注。周次变化时，备注按同课程/星期/节次唯一匹配迁移，歧义不自动匹配。连续节次卡片跨越对应网格行；同日冲突课程分栏。网站教师字段仅有标点时显示“教师待补充”。
6. 作业支持修正标题、DDL、个人备注及本地完成状态；“恢复平台数据”清除本地覆盖，不会向网站提交作业或改动状态。
7. 开启本地提醒并授权，或发 15 秒测试通知。点击通知进入课表作业页。

Gradescope 带 offset 的日期直接转换（包括 `2026-10-20 23:59:00 +0800`），排除发布时间；仅显示当地时间的日期须由用户确认页面时区，未确认则标记“截止时间待确认”。正常截止和补交截止分别保存。BB 使用上海时区。未提交优先于“submitted”子串与可见分数。

## 限制与故障行为

- 支持应用内手动同步及 Android 挂件后台同步；后台执行受系统省电调度限制。学校/网站改版可能需要调整解析器；不把无法识别的页面当成无作业。
- 提醒滚动保存最近最多 400 条，打开应用、同步或修改配置时重排；不会持续在后台补充后续窗口。
- Android 无精确闹钟权限时使用系统非精确排程并提示可能延迟，厂商省电限制仍可能影响触发；强行停止应用会取消系统闹钟，重新打开应用后重排。
- 数据持久化、派生投影和系统闹钟不是跨层数据库事务。配置和投影失败尽力恢复旧值；提醒失败独立提示，不把数据同步成功改称失败。
- 会话由 Android WebView 保存在应用私有目录，禁用应用备份；不保存密码、不导出 Cookie。正式会话与 debug 登录探针隔离。
- iOS 分支已接入三平台官方网页登录与会话桥、本地通知桥；iOS 通知实际展示与点击待专项验收，后台联网与 Android 不同。完整范围见 [iOS 功能说明](../../../../../../docs/ios-features.md)。Web 不支持平台网页登录及本地提醒，会明确显示不可用。
- 本轮未实现 Gradescope 题目下载、附件缓存、自动交作业或成绩管理。

## 验证

`npm run check` 包含学业专项测试：本期分组、春秋边界与跨年、历史及未来学期不入请求队列、旧缓存与无日期过滤、可靠空列表、历史提醒撤销、学期/时区/补交/中文日期、教务断续周/周末/不连续节、重复同步、备注跨同步及重启保留、失败保留快照、通知故障与同步结果分离、origin/端口会话隔离，以及 GET 限流后续读、POST 限流不自动重发。

真实样本仅存 gitignored `private-fixtures`。debug 探针与正式插件分开验收，不把探针成功当成正式插件同步成功。

以下为 2026-10-17 历史全量版本结果，数量不代表当前本学期范围。全仓 `npm run check`、前端打包与 Android `assembleDebug` 已通过，APK 已安装到 vivo V2352A。正式网页登录由用户完成，随后通过 UI、宿主网关与插件同步：

| 平台 | 课程 | 作业 / 排课 | 日期识别 |
|---|---:|---:|---|
| Gradescope | 7 | 77 项作业 | 76 项正常 DDL，63 项补交 DDL |
| Blackboard | 25 | 93 项作业 | 85 项正常 DDL |
| 教务 | 7 | 20 条排课 | 13 节作息；学期起始日期待用户填写 |

教务重新同步后，3–4 节课程的 DOM 为 `grid-row: 4 / span 2`，真机高度约 174 px，实际占据两行。通过课程详情填写临时备注、保存、重新同步后备注仍在；测试后已恢复原有修正。仅标点教师字段已显示“教师待补充”。强停并重启应用后，三个平台的快照与 DDL 数量保持一致，跨节布局仍正常。

约 15 秒测试通知的显示、点击返回、同 ID 覆盖、取消与 pending 对账已在真机验证。用户选择稍后填写第 1 教学周日期，当前保持为空；本地提醒开关仍关闭，未生成上课日期或排程生产提醒。开机恢复、长期后台触发尚未实测，当前没有后台自动联网。
