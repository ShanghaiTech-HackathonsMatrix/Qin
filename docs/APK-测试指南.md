# Matrix 验证版 APK —— 实机测试指南

## 这是什么

一个**最小可运行**的 Android 应用，用来在真机上验证设计文档里那些「纸面上成立、但没在设备上跑过」的部分。

它**不是**完整产品。当前包含：

- 时间线（DDL / 课程 / 测验 / 签到 / 自定义条目）
- 课程管理
- 布局、密度、主题色切换
- **可切换的策略层**（上一轮的重点）
- **核心层：网络网关 + 凭证库 + 能力令牌 + 审计**（本轮新增）
- 隐藏的调试面板（策略 + 核心层）

**尚未包含**：插件系统（QuickJS 沙箱）、微信解析、通知监听、认证代理的登录流程。

## 提供了两个 APK，先装哪个？

| 文件 | 权限 | 用途 |
|---|---|---|
| `matrix-debug.apk` | 含 `INTERNET` | **先装这个**。本轮的重点验证都在它上面 |
| `matrix-nonet.apk` | **无 `INTERNET`** | 验证「WebView 自身零网络」这条主张（见下，含义已变） |

两者代码完全相同，只差清单里的 `INTERNET` 权限。因为 applicationId 相同，
**它们不能同时安装** —— 装第二个会覆盖第一个。

### ⚠️ nonet 版本的含义本轮变了，请先读这段

上一轮，这个应用**根本不发任何真实网络请求**，所以去掉 `INTERNET` 权限它照样一切正常，
用来证明「WebView 不需要网络权限」。

本轮不一样了：核心层会**真的发请求**，走的是 `CapacitorHttp` → 原生 `HttpURLConnection`。
**这条路是应用进程发的，需要 `INTERNET` 权限。**

所以 `matrix-nonet.apk` 现在的预期行为是：

| 操作 | 预期 |
|---|---|
| 打开应用、增删改查、切策略 | ✅ 全部正常（WebView 依然零网络） |
| 调试面板里「只判定（不发请求）」 | ✅ 正常工作 —— 纯本地逻辑 |
| 调试面板里「真发一次请求」 | ❌ 失败，错误码 `ENET`（没有网络权限） |

**这恰好是一次漂亮的对照实验**：同一个功能，去掉权限就发不出去，
说明请求确实是**原生进程**发的，而不是 WebView 偷偷发的 —— 网络收口这条防线是真的。

如果 nonet 版本里「真发一次请求」**居然成功了**，那是个严重问题，请立刻告诉我：
说明有某条路径绕过了核心层直接出网。

## 本轮新增：核心层（这是本轮要测的重点）

### 它是什么

设计文档里，全系统**只有一个地方允许出网**：核心层。所有请求都要依次过

```
能力令牌 → URL 校验 → 域名白名单 → 限流 → 注入会话 → 发出
        → 逐跳复检白名单 → 响应大小上限 → 剥离 Set-Cookie → 审计
```

插件拿不到网络能力，也拿不到 cookie —— 它只能提交一个 URL，然后由核心层决定发不发。

**这一轮全部用 TypeScript 写**，没有一行 Kotlin。原因是核实了 `@capacitor/core` 自带的
`CapacitorHttp` 插件本来就提供原生传输层，`plugins.CapacitorHttp.enabled` 保持 `false`
（WebView 依然零网络），但插件本身可以直接调用。详见 `DESIGN.md` §7.4。

### 怎么测

1. 进 **设置** → 最下方 **关于** → **连点「版本」那一行 5 次**
2. 弹出调试面板，往下滚到 **「核心层（网络出口 / 凭证库）」**
3. 这里能看到：传输层、凭证库保护强度、各项限额、白名单、审计记录

然后按顺序做这四件事：

#### ① 看「只判定」能不能拦住不该发的请求

在「试一下」输入框里依次试这几个 URL，点 **「只判定（不发请求）」**：

| 输入 | 期望结果 |
|---|---|
| `https://evil.com/` | ✗ 拒绝（`EHOST`）主机不在白名单内 |
| `http://api.github.com/zen` | ✗ 拒绝（`EURL`）只允许 https |
| `https://127.0.0.1/` | ✗ 拒绝（`EIP`）不允许 IP 字面量 |
| `https://2130706433/` | ✗ 拒绝（`EIP`）十进制整数形式的 IP 也拦 |
| `https://good.com@evil.com/` | ✗ 拒绝（`EURL`）userinfo 视觉欺骗 |

**注意白名单此时是空的**，所以连正常域名也会被拒 —— 这是刻意的默认值（默认拒绝）。

#### ② 加一条白名单，再试一次

在白名单输入框里填：

```
api.github.com
```

点 **「保存并生效」**。然后再试：

| 输入 | 期望 |
|---|---|
| `https://api.github.com/zen` | ✓ 允许 |
| `https://gist.github.com/` | ✗ 拒绝 —— **精确规则不匹配子域** |

再把白名单改成 `*.github.com`，重新保存：

| 输入 | 期望 |
|---|---|
| `https://gist.github.com/` | ✓ 允许（任意层子域） |
| `https://github.com/` | ✗ 拒绝 —— **通配符不含根域**（刻意的） |

#### ③ 真发一次请求

白名单里保留 `api.github.com`，输入 `https://api.github.com/zen`，点 **「真发一次请求」**。

期望：`✓ HTTP 200 · N 字节 · Nms · 1 跳`

然后往下看**审计记录**，应当出现一条：`放行 GET api.github.com/zen · HTTP 200 · …`

这一步同时验证了：网络真的通了、`CapacitorHttp` 在 `enabled: false` 下确实可用、
审计在记录。

#### ④ 验证审计与落盘

- 随便再发几次（包括几次被拒的「只判定」**不会**进审计，只有真发请求才进）
- 点 **「立即落盘」**，看「已写」次数 +1
- **完全杀掉应用**，重新打开，再进调试面板 —— 审计记录应当还在（落盘到系统安全存储里了）

> **这一条曾经是坏的，已修。** 上一版的症状是：重启后面板显示「缓冲 N 条」，
> 但**列表是空的**。原因是记录被读回了存储封装自己的缓冲，而面板读的是核心层另一个
> 环形缓冲，两者从未接上。现在启动时会把读回的记录灌进核心层缓冲，
> 统计数字也会一起恢复（不会出现「列表有 12 条、表头统计却是 0」）。
> 如果这次重启后列表**仍然**为空，请告诉我 —— 那说明还有第二处没接上。

#### ⑤ 对比两种会话后端（本轮新发现的东西）

在核心层区块里有一个 **「会话后端」** 开关，可以在 `memory（隔离）` 和
`capacitor-cookies（原生）` 之间切换。点一下切换，然后再发几次请求。

**要观察的**：切到 `capacitor-cookies` 后，审计条目里出现「收走 N 个 cookie」的记录 ——
说明 Set-Cookie 被核心层收走并登记了。而 `memory` 后端下 cookie 只留在 JS 内存里。

> **⚠️ 要看到「收走 N 个 cookie」，请求的站点必须真的种 cookie。**
> `api.github.com/zen` **不种 cookie**，所以对它请求多少次都不会出现这一行 ——
> 这不是功能没生效。请改用一个会 `Set-Cookie` 的地址，例如
> `https://httpbingo.org/cookies/set?matrix=hello`（它设完 cookie 会 302 到 `/cookies`，
> 顺带还能看到「经 2 跳」和逐跳复检都在工作）。
>
> 调试面板的请求现在会带上一个固定的调试会话（`debug-panel`），
> 面板上会显示「当前持有 N 条 cookie」。第一次请求后 N 应当变成 1，再发一次，
> 这次请求就会**带上**那个 cookie —— 会话注入的闭环就这么验证。
> （首次请求后 N 没变，说明该站点确实没种 cookie，换个地址再试。）

**更重要的是下面这件事**：我在核查源码时发现，`CapacitorHttp` 的原生 cookie 存储是
**进程全局**的（`CapacitorCookies.java:26` 装了全局 `CookieHandler`，而插件注册时
无条件执行 `load()`），**从 JS 关不掉**。也就是说：

- ✅ 插件**看不到** cookie 内容（我们从响应头里剥掉了 `set-cookie`）
- ❌ 但**插件之间不隔离** —— 插件 A 在某站点的会话 cookie，会被插件 B 对该站点的请求自动带上

这一条与设计文档 §8.2 的假设冲突，已在文档里如实记录。当前无纯 TS 的解法，
需要自写原生代码换掉那个全局 handler。**这不是本轮能修的，但你应当知道它存在。**

另外注意审计条目里可能出现的两个标记：

| 标记 | 含义 |
|---|---|
| `JSON 往返` | 响应体被传输层解析又序列化过，**不是线上原始字节**（`CapacitorHttp` 在 content-type 是 JSON 时忽略 `responseType`，原生和 Web 都一样） |
| `⚠️ N 个大整数可能丢精度` | 上面这个往返的后果：> 2^53-1 的整数会被静默改成别的数 |

试着请求一个返回大整数的接口就能看到第二个标记（例如某些返回雪花 ID 的 API）。

## 安装

1. 把 `matrix-debug.apk` 传到手机（USB、网盘、微信文件传输都行）
2. 在手机上点开它
3. 系统会提示「不允许安装未知来源应用」→ 按提示去设置里允许该来源
4. 安装完成后打开 **Matrix**

> debug 签名的调试包，不能上架应用商店，仅供内部测试。

## 上一轮的测试项（仍然值得再确认一次）

### ① 启动自检是否选到了理想策略

**设置** 页看「运行状态」：

| 期望 | 说明 |
|---|---|
| 存储后端 | `sqlite+sqlcipher/generated` —— 加密库 + 生成列索引 |
| 键值存储 | `kv.secure-storage` —— 走 Android Keystore |
| 索引策略 | `indexing.generated-columns` |

**如果看到黄色「已降级运行」告警**，请截图发我。

### ② 数据是否真的持久化

加 3 门课、5 条 DDL → 完全杀掉应用 → 重新打开 → 数据应当还在。再重启手机确认一次。

### ③ 策略能否快速切换

调试面板里点任意策略 → 「应用并重新自检」。切换存储后端时，若目标后端为空会自动迁移数据。

### ④ 布局与主题

设置页里切主题色、密度、时间线布局，应当即时生效且重启后保持。

### ⑤ 离线可用性

开**飞行模式**，重复 ①～④。除核心层的「真发一次请求」外，全部功能应当不受影响。

## 已知限制（不是 bug）

| 现象 | 原因 |
|---|---|
| 白名单初始为空，什么都发不出去 | **刻意的**，与「默认拒绝」的设计一致 |
| 顶部副标题显示「密钥未受保护」 | KV 降级到了 Preferences/localStorage，Keystore 不可用 |
| 切到 JSON 存储后大量数据变慢 | 该方案无索引无事务，是设计上的降级路径 |
| 审计最多可能丢最近 1.5 秒的记录 | 合并写：牺牲这点换来请求延迟不受影响 |
| 没有登录 / OAuth 界面 | 认证代理只做了会话与 cookie 部分，登录流程在下一阶段 |
| 桌面图标是默认的 | 还没做图标 |

|---|---|---|

| CSP 已注入产物 | ✅ | 打包的 `index.html` 含 `connect-src 'none'` |
| 逐跳复检有原生支持 | ✅ | 原生 `HttpRequestHandler.java:392/422` 读取并应用 `disableRedirects` |
| SQLCipher 真的编进去了 | ✅ | APK 内含 4 个 ABI 的 `libsqlcipher.so` |
| 加密连接改用 `mode: 'secret'` | ✅ | bundle 内为 `f.encrypted?"secret":"no-encryption"` |
| 加密库与明文库文件名已分离 | ✅ | bundle 内含 `matrix_timeline_enc` |
| 降级次序改为显式 `order` | ✅ | `store.json` 的 order=20，排在 `store.sqlite`(10) 之后 |
| 核心层逻辑本机跑通 | ✅ | `node src/core/conformance.test.ts` —— **83 项断言全过** |
| Web 同构适配器确实存在 | ✅ | `@capacitor/core` dist 里 `CapacitorHttpPluginWeb`（L498）的 `request()` 用 `window.fetch` |
| `set-cookie` 会被剥掉 | ✅ | 有专门用例断言响应头里不出现 cookie 明文 |
| JSON 往返与大整数告警 | ✅ | 有用例覆盖（含时间戳不误报、小数不误报） |

**真机已确认（Android 16 / API 36）**：

| 项目 | 结果 |
|---|---|
| `PRAGMA cipher_version` 非空 | ✅ 加密真实生效 |
| Keystore 写-读-删往返 | ✅ 成功，`kv.secure-storage` 被选中 |
| 生成列 + 索引可用 | ✅ 可用，`indexing.generated-columns` 被选中，未走影子表退路 |
| 三个槽位是否都选中理想策略 | ✅ 是（`store.sqlcipher` + `kv.secure-storage` + `indexing.generated-columns`） |
| 无 `INTERNET` 权限能否正常运行 | ✅ 能。`matrix-nonet.apk` 功能完整，但真发请求按预期失败（`ENET`）—— 这正是「请求由原生进程发起」的反证 |
| 核心层真实请求能否发出 | ✅ HTTP 200；302 跳转正常，逐跳复检在工作（审计显示「经 2 跳」） |

**纸面推演看不出的缺陷（真机跑出来的，均已修复）**：加密库 `mode` 语义误用、降级排序、
库名冲突、切换迁移缺失、`set-cookie` 泄漏给插件、**审计读回了却不显示**（读进的是存储封装
的缓冲，面板读的是核心层另一个缓冲）。最后一条尤其说明问题：纸面上「审计已持久化」是成立的，
但用户看到的是空列表 —— **功能存在 ≠ 功能可用**。

## 技术背景（想深究可以看）

- 应用 ID：`dev.matrix.shell`
- 最低支持 Android 7.0（API 24），目标 API 36
- CSP：`connect-src 'none'`（WebView 自身不发起任何网络请求）
- 数据库：`matrix_timeline`（SQLCipher 加密时口令存在 KV 策略里）
- 核心层：`apps/shell/src/core/`，纯 TypeScript，本机 83 项断言

对应设计文档：`docs/design/DESIGN.md`
P0 验证报告：`spikes/p0/REPORT.md`
