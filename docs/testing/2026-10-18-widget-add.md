# Android 挂件添加兼容修复

基线：main `f8ab2ce`。仅修改 Android 与其设置界面，未合入 iOS 分支。

## 行为

- 设置页独立查询当前桌面是否支持请求固定挂件，以及本应用的挂件数量。不支持时显示手动指引，不承诺每个 Android 桌面都能弹窗。
- 原生固定请求返回只表示已请求。通过非导出 Receiver 接收显式、不可变、单次 PendingIntent 的成功回调；请求令牌校验避免旧回调确认新请求。
- 请求前保存已有挂件 ID，查询时以新增 ID 辅助确认。已有挂件、总数量未变和删除旧挂件不会直接等同于本次成功。
- 请求状态保存在本机，可跨进程重建核对。15 秒未确认只显示“尚未确认”，仍接受迟到的成功回调；不是把取消、无弹窗或超时武断判为失败。
- 回到设置页及页面可见时重新检测。反馈紧邻按钮，常驻“长按桌面 → 小组件 / 挂件 / 安卓组件 → 秦QIN”的操作说明。
- 系统异常转换为界面错误；界面等待原生添加调用最多 8 秒，之后解除操作锁并继续检测。未改变 BB、Gradescope、教务同步及挂件内容。

## 验证

- 全仓 `npm run check`（含新增 5 项前端测试）通过。
- Android Java 编译及预览 APK 构建通过。Gradle `testDebugUnitTest` 执行器在本机报测试类 `ClassNotFoundException`，原有测试同样受影响；导出该任务的完整 classpath，直接使用 JUnitCore 运行新增及原有挂件测试，共 10 项通过。未将 Gradle 测试任务记录为通过。
- vivo V2352A 覆盖安装、启动通过。原生实际返回 `supported=true`、`widgetCount=0`，点击后桌面没有弹窗；随后返回 `unconfirmed`，界面在按钮旁显示“尚未确认添加”及手动指引，没有报添加成功。
- 最后一处调整为“系统接受请求后直接返回 requested，交由后续查询核对”，重新构建并通过上述 10 项 JUnit 测试。最新 APK 已导出到 `dist-apk/Qin-widget-add-fix-preview.apk`；自动覆盖安装曾被手机拒绝（`INSTALL_FAILED_ABORTED: User rejected permissions`）。随后用户反馈“实机测试功能正常”，确认本轮修复可用；未提供具体机型及各分支操作记录。
- 支持系统弹窗的其他桌面、真实成功回调、手动新增后的数量变化及重启后恢复仍需专项设备验收。单元测试覆盖这些状态判定，不替代桌面实际行为的验证。

设备截图、临时测试 classpath 与 APK 存在 gitignored 目录，不入库。系统桌面仍掌握弹窗与放置权限，本修复不绕过系统限制。
